# GAVFS Reference — Version 1.0 (Draft)

The General Autonomous Vehicle Feed Specification (GAVFS) defines a common format for publishing information about autonomous ride-hailing services. This document is the normative reference for GAVFS 1.0. The specification is under development and may change before release.

## Motivation

Autonomous ride-hailing providers increasingly operate alongside public transit and other shared mobility services. Without a common, provider-neutral data interface, mapping and trip-planning applications must develop separate integrations to discover coverage, estimate wait times and fares, and send riders to booking. This limits service visibility and makes multimodal comparisons harder.

GAVFS provides a consistent, rider-facing data interface so providers can publish where service is offered, which ride products are available, and what a proposed trip might cost or how long pickup may take. It enables third-party applications to include autonomous ride-hailing in travel planning while leaving booking, dispatch and payment with the provider.

## Introduction

A GAVFS dataset represents **one consumer-facing autonomous ride-hailing provider**. A provider publishes static resources describing its identity, service areas and ride products, along with dynamic endpoints for pickup estimates and trip planning. A consuming application can use this information to display service coverage, compare ride options and open a provider-generated booking link.

GAVFS does not define dispatch, payment, rider account creation, confirmed reservations or trip cancellation.

### Terminology

| Term | Definition |
| --- | --- |
| Provider | Consumer-facing service offering autonomous ride-hailing trips |
| Consumer | Application retrieving and displaying GAVFS information |
| Rider | Person who may book a ride through the provider |
| Feed | A GAVFS dataset and its associated endpoints |
| Product | A bookable class of ride offered by a provider |
| Service area | Geographic region with provider-defined pickup and dropoff rules |

The key words **MUST**, **MUST NOT**, **REQUIRED**, **SHOULD**, **SHOULD NOT**, **RECOMMENDED**, **MAY** and **OPTIONAL** are to be interpreted as described in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) and [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174) when they appear in uppercase.

## General requirements

- A GAVFS dataset MUST describe exactly one provider.
- The provider MUST make a `gavfs.json` discovery file available over HTTPS.
- Every advertised resource URL MUST use HTTPS.
- JSON responses MUST be encoded as UTF-8 and use the `application/json` media type.
- All resources MUST contain `last_updated` and `data` at the root. The discovery file MUST additionally contain `version`.
- Times MUST be RFC 3339 timestamps; timezone identifiers MUST follow the IANA timezone database.
- Latitude and longitude MUST be WGS 84 decimal degrees. GeoJSON coordinates use **longitude, latitude** order.
- Durations MUST be expressed in seconds, distances in meters, and currencies as ISO 4217 codes.
- A provider MAY require consumer application API keys for rate limiting. Retrieving ride information MUST NOT require rider authentication.
- Consumers SHOULD respect HTTP cache headers and rate limits.

### Hosting and discovery

Providers MUST publish a `gavfs.json` manifest at a stable HTTPS URL. A RECOMMENDED layout is `https://api.example.com/gavfs/gavfs.json`, but feed resources MAY be hosted on different HTTPS paths. Consumers MUST use URLs advertised in the manifest.

#### Well-known discovery document

Providers SHOULD expose an unauthenticated JSON discovery document at `https://example.com/.well-known/gavfs` on their public-facing domain. This resource is **discovery metadata**, not the GAVFS manifest itself. The path is a proposed GAVFS convention and is not yet an IANA-registered well-known URI.

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `active` | Boolean | REQUIRED | Whether this provider currently advertises an active GAVFS integration |
| `url` | HTTPS URL | CONDITIONAL | Absolute URL of the provider's `gavfs.json` manifest; REQUIRED when `active` is `true` |
| `auth_needed` | Boolean | REQUIRED | Whether consumer application credentials are required to access advertised GAVFS resources |
| `docs` | HTTPS URL | OPTIONAL | Provider's integration documentation, including instructions for obtaining credentials if needed |

Example using a **hypothetical** Uber integration (this is not an assertion that Uber publishes GAVFS):

```json
{
  "active": true,
  "url": "https://api.uber.com/gavfs/gavfs.json",
  "auth_needed": true,
  "docs": "https://developer.uber.com/docs/gavfs"
}
```

`active: false` indicates that the provider is not currently advertising an active integration. Consumers MUST NOT infer service availability from an inactive discovery document. If `active` is `true`, consumers MAY follow `url` to retrieve the manifest. If `auth_needed` is `true`, the provider MAY require application-level credentials; **the discovery document itself MUST remain accessible without authentication**, and GAVFS information queries MUST NOT require rider account authentication. `docs` SHOULD explain the credential acquisition process when applicable.

Consumers MUST NOT assume that `auth_needed: false` guarantees unlimited anonymous access; providers MAY still enforce rate limits. The well-known discovery document SHOULD be served with `application/json` and appropriate HTTP cache headers.

### Feed discovery

`gavfs.json` is the entry point for the dataset. Each entry in `data.feeds` identifies a resource name and absolute HTTPS URL. The discovery file MUST advertise `provider`, `service_areas`, `products`, `eta`, and `trip_planning`. It MAY advertise `service_status`.

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `version` | String | REQUIRED | GAVFS specification version, currently `1.0` |
| `last_updated` | Timestamp | REQUIRED | Time the discovery response was last updated |
| `data.feeds` | Array of objects | REQUIRED | Available feed resources |
| `data.feeds[].name` | String | REQUIRED | Registered resource name |
| `data.feeds[].url` | URL | REQUIRED | Absolute HTTPS URL for the resource |

See [example discovery response](../examples/manifest.json).

## Feed reference

### provider.json

**Type:** Static JSON resource  
**Presence:** REQUIRED

Describes the provider represented by the GAVFS dataset. Exactly one provider is described in this resource. The provider is implicit in all other resources; consumers do not need a repeated `provider_id` on each product or service area.

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `provider_id` | String | REQUIRED | Stable provider identifier |
| `name` | String | REQUIRED | Public-facing provider name |
| `url` | URL | REQUIRED | Provider website |
| `timezone` | String | REQUIRED | IANA timezone identifier |
| `language` | String | REQUIRED | Primary BCP 47 language tag |
| `support.phone` | String | OPTIONAL | Rider support phone number |
| `support.url` | URL | OPTIONAL | Rider support website |
| `booking.deep_link` | URI | REQUIRED | Base URI for opening the provider's booking app |
| `booking.web_url` | URL | OPTIONAL | Web booking entry point |
| `booking.app_store_url` | URL | OPTIONAL | iOS app installation page |
| `booking.play_store_url` | URL | OPTIONAL | Android app installation page |

Fields in this table are members of the response's `data` object. The base booking link is informational; a consumer MUST use the trip-specific link returned by `trip_planning` when handing off a planned trip.

See [example provider response](../examples/provider.json).

### service_areas.json

**Type:** Static JSON resource  
**Presence:** REQUIRED

Lists geographic areas in which the provider offers service. An area MAY restrict pickup, dropoff or both. Geometry MUST be a GeoJSON Polygon or MultiPolygon.

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `service_areas` | Array | REQUIRED | List of service area objects |
| `service_areas[].area_id` | String | REQUIRED | Identifier unique within this dataset |
| `service_areas[].name` | String | REQUIRED | Rider-facing area name |
| `service_areas[].geometry` | GeoJSON geometry | REQUIRED | Service boundary |
| `service_areas[].pickup_allowed` | Boolean | REQUIRED | Whether pickup is allowed within the area |
| `service_areas[].dropoff_allowed` | Boolean | REQUIRED | Whether dropoff is allowed within the area |
| `service_areas[].has_surge` | Boolean | REQUIRED | Whether surge pricing may be applied to trips originating in the area |

**Surge pricing:** `has_surge: true` means the provider may use surge pricing for trips originating in the area. It does not indicate that surge is currently active. `has_surge: false` means the provider does not use surge pricing for trips originating in the area. Consumers MUST retrieve trip-specific fares from `trip_planning`.

Service areas SHOULD avoid overlapping polygons with contradictory rules. If overlaps are necessary, the provider SHOULD document how the rules are resolved.

See [example service areas response](../examples/service_areas.json).

### products.json

**Type:** Static JSON resource  
**Presence:** REQUIRED

Lists ride products offered by the provider.

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `products` | Array | REQUIRED | List of products |
| `products[].product_id` | String | REQUIRED | Product identifier unique within the dataset |
| `products[].name` | String | REQUIRED | Rider-facing product name |
| `products[].description` | String | OPTIONAL | Product description |
| `products[].capacity.passengers` | Nonnegative integer | OPTIONAL | Passenger capacity |
| `products[].capacity.wheelchairs` | Nonnegative integer | OPTIONAL | Wheelchair capacity |
| `products[].amenities` | Array of strings | OPTIONAL | Amenities available with the product |
| `products[].accessibility.wheelchair_accessible` | Boolean | OPTIONAL | Whether the product supports wheelchair boarding |
| `products[].accessibility.service_animals_allowed` | Boolean | OPTIONAL | Whether service animals are accommodated |

Consumers SHOULD ignore unknown amenity strings without failing to parse the product. Accessibility information SHOULD reflect actual available service, not assumptions based on vehicle type.

See [example products response](../examples/products.json).

### eta

**Type:** Dynamic HTTP GET endpoint  
**Presence:** REQUIRED

Returns estimated pickup times at a specified origin. The endpoint MUST accept the following query parameters:

| Parameter | Type | Presence | Description |
| --- | --- | --- | --- |
| `lat` | Latitude | REQUIRED | Requested pickup latitude |
| `lon` | Longitude | REQUIRED | Requested pickup longitude |

Response fields, relative to `data`:

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `location.lat` | Latitude | REQUIRED | Queried latitude |
| `location.lon` | Longitude | REQUIRED | Queried longitude |
| `estimates` | Array | REQUIRED | Available product-specific pickup estimates |
| `estimates[].product_id` | String | REQUIRED | Product identifier from `products.json` |
| `estimates[].pickup_eta_seconds` | Nonnegative integer | REQUIRED | Estimated time until pickup in seconds |

An empty `estimates` array indicates that no pickup estimate is available for the query. Pickup estimates do not represent reservations.

See [example ETA response](../examples/eta.json).

### trip_planning

**Type:** Dynamic HTTP GET endpoint  
**Presence:** REQUIRED

Returns available ride options for an origin-destination pair and a provider-generated link to continue booking.

Request parameters:

| Parameter | Type | Presence | Description |
| --- | --- | --- | --- |
| `start_lat` | Latitude | REQUIRED | Origin latitude |
| `start_lon` | Longitude | REQUIRED | Origin longitude |
| `end_lat` | Latitude | REQUIRED | Destination latitude |
| `end_lon` | Longitude | REQUIRED | Destination longitude |
| `passengers` | Positive integer | OPTIONAL | Number of passengers |
| `product_id` | String | OPTIONAL | Requested ride product |

Response fields, relative to `data`:

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `trips` | Array | REQUIRED | Trip options for the query |
| `trips[].trip_id` | String | OPTIONAL | Provider-issued reference for the estimate |
| `trips[].product_id` | String | REQUIRED | Product identifier from `products.json` |
| `trips[].pickup_eta_seconds` | Nonnegative integer | REQUIRED | Estimated pickup wait |
| `trips[].duration_seconds` | Nonnegative integer | REQUIRED | Estimated in-vehicle duration |
| `trips[].distance_meters` | Nonnegative number | OPTIONAL | Estimated trip distance |
| `trips[].pickup` | Coordinate object | OPTIONAL | Proposed pickup location |
| `trips[].dropoff` | Coordinate object | OPTIONAL | Proposed dropoff location |
| `trips[].fare` | Fare object | REQUIRED | Fare estimate or guaranteed quote |
| `trips[].booking.deep_link` | URI | REQUIRED | Fully formed provider-generated booking handoff link |
| `trips[].booking.web_url` | URL | OPTIONAL | Browser-based booking fallback |

Coordinate objects contain `lat` and `lon` numeric members. Consumers MUST NOT construct booking URLs from the base link in `provider.json` when a trip-specific booking link is provided. Opening a booking URL does not confirm a trip.

#### Fare object

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `currency` | String | REQUIRED | ISO 4217 currency code |
| `type` | Enum | REQUIRED | `estimated`, `estimated_range` or `guaranteed` |
| `amount` | Nonnegative number | CONDITIONAL | REQUIRED for `estimated` and `guaranteed` |
| `minimum` | Nonnegative number | CONDITIONAL | REQUIRED for `estimated_range` |
| `maximum` | Nonnegative number | CONDITIONAL | REQUIRED for `estimated_range` |
| `expires_at` | Timestamp | OPTIONAL | Time through which the returned fare amount or range remains valid |

When `expires_at` is present, it MUST be an RFC 3339 timestamp later than the response's `last_updated`. Consumers SHOULD refresh the trip estimate after this time and MUST NOT display an expired amount as current. `expires_at` indicates a price validity window; it does not automatically guarantee a fare or reserve a vehicle. A fare is guaranteed only when `type` is `guaranteed` and the provider honors that guarantee.

When `type` is `estimated_range`, `minimum` MUST NOT exceed `maximum`. Estimated fares SHOULD closely reflect the amount shown when the rider opens the provider's app, but minor differences may arise from elapsed time, surge pricing or changes in conditions. Consumers MUST identify estimates as estimates. `guaranteed` MUST only be used when the provider commits to honoring the quoted amount under its published conditions.

See [example trip planning response](../examples/trip_planning.json).

### service_status.json

**Type:** Static or periodically refreshed JSON resource  
**Presence:** OPTIONAL

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `status` | Enum | REQUIRED | `operating`, `limited` or `suspended` |
| `message` | String or null | OPTIONAL | Rider-facing status information |

See [example service status response](../examples/service_status.json).

## HTTP responses and error handling

| Status | Meaning | Consumer behavior |
| --- | --- | --- |
| `200` | Successful response | Parse the response |
| `400` | Invalid request parameters | Correct request parameters |
| `401` or `403` | Application credential absent or rejected | Do not request rider credentials |
| `429` | Consumer application rate limited | Respect `Retry-After` when present |
| `5xx` | Provider error | Avoid presenting stale estimates as current |

Providers SHOULD return machine-readable JSON errors. Consumers SHOULD distinguish unavailable rides from provider outages. A valid `200` response with an empty `trips` array means that no trip options were returned.

## Security and privacy

GAVFS consumers MUST NOT be required to transmit rider account credentials for information queries. Providers MAY use application-level authentication for access control and rate limiting. Provider-generated booking links SHOULD avoid embedding personal data or reusable rider credentials. Consumers SHOULD minimize retention of precise coordinates.

## Versioning and compatibility

GAVFS 1.0 defines the resource names and fields documented here. Providers MUST advertise the version in `gavfs.json`. Consumers SHOULD ignore unrecognized optional fields where practical and MUST NOT assume that undocumented extensions are standardized.
